# 部署方案建议

## 当前情况
- 前端：Taro 4，部署在 Vercel
- 后端：NestJS 10，部署在 Vercel Serverless
- 数据库：Supabase PostgreSQL
- 域名：阿里云申请（已备案）

## 方案对比

### 方案 A：继续使用 Vercel（推荐）

#### 优点
- ✅ 无需迁移代码
- ✅ 自动 HTTPS 证书
- ✅ 全球 CDN 加速
- ✅ 免费/低成本（Hobby Plan）
- ✅ 自动扩缩容
- ✅ 零服务器维护

#### 缺点
- ⚠️ Serverless 冷启动（1-3秒）
- ⚠️ 支付回调可能超时（微信要求5秒内响应）

#### 适用场景
- 初期流量不大（<1000 单/天）
- 冷启动延迟可接受
- 预算有限

#### 配置步骤
1. 在 Vercel 项目中添加自定义域名
2. 配置 DNS 解析（CNAME）
3. 等待 SSL 证书自动配置
4. 测试 HTTPS 访问

---

### 方案 B：迁移到阿里云 ECS

#### 优点
- ✅ 无冷启动延迟
- ✅ 支付回调实时响应
- ✅ 完全控制服务器
- ✅ 适合高并发场景

#### 缺点
- ❌ 需要购买服务器（¥50+/月）
- ❌ 需要手动配置 HTTPS 证书
- ❌ 需要维护服务器（安全、更新、备份）
- ❌ 需要迁移代码
- ❌ 需要配置 Nginx/PM2

#### 适用场景
- 高并发场景（>1000 单/天）
- 对延迟敏感
- 有运维经验

#### 配置步骤
1. 购买阿里云 ECS 服务器
2. 安装 Node.js、PM2、Nginx
3. 上传代码并部署
4. 配置 SSL 证书（阿里云免费证书）
5. 配置 Nginx 反向代理
6. 开放防火墙端口
7. 测试 HTTPS 访问

---

## 推荐方案

### 阶段一：先用 Vercel（推荐）

**原因：**
1. 项目初期，流量不大
2. 冷启动延迟可接受
3. 成本低，维护简单
4. 快速上线测试

**配置微信支付回调地址：**
```
https://你的域名.vercel.app/api/payment/callback/wechat
# 或自定义域名
https://你的自定义域名/api/payment/callback/wechat
```

---

### 阶段二：流量增长后迁移到 ECS（可选）

**迁移时机：**
- 冷启动延迟影响用户体验
- 支付回调超时率 >1%
- 日订单量 >1000
- 需要更多服务器资源

**迁移步骤：**
1. 购买阿里云 ECS
2. 配置服务器环境
3. 迁移代码和数据
4. 切换域名解析
5. 灰度发布测试
6. 正式切换

## Vercel 自定义域名配置

### 步骤 1：在 Vercel 添加域名
1. 进入 Vercel 项目 → Settings → Domains
2. 输入你的域名（如 `api.yourdomain.com`）
3. Vercel 会提示添加 DNS 记录

### 步骤 2：配置 DNS 解析
在阿里云 DNS 控制台添加 CNAME 记录：
```
类型：CNAME
主机记录：api
记录值：cname.vercel-dns.com
TTL：600
```

### 步骤 3：等待 SSL 证书配置
- Vercel 会自动配置 Let's Encrypt SSL 证书
- 通常 1-5 分钟完成
- 访问 `https://api.yourdomain.com` 验证

## 决策建议

### 选择 Vercel，如果：
- ✅ 初期项目，流量不大
- ✅ 预算有限
- ✅ 无运维经验
- ✅ 希望快速上线

### 选择 ECS，如果：
- ✅ 预期高并发
- ✅ 对延迟敏感
- ✅ 有运维经验
- ✅ 需要更多自定义配置

---

## 总结

**推荐流程：**
1. 先用 Vercel 快速上线（成本 $0）
2. 测试支付功能和用户体验
3. 根据实际流量决定是否迁移到 ECS
4. 迁移前确保有运维资源

**避免过度设计：**
- 不要一开始就上 ECS（成本高、维护复杂）
- 不要等到系统崩溃才迁移（提前规划）
- 不要忽视冷启动问题（监控回调超时率）
