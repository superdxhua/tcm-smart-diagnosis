# 获取健康方案失败修复说明

## 问题描述

**用户反馈**：
- 获取健康方案功能反复失败，一直无法正常使用
- 之前多次尝试修复，但问题仍然存在

**失败现象**：
- 前端点击"生成健康方案"后，加载动画一直显示
- 最终显示"获取健康方案失败，请重试"
- 控制台没有明确的错误提示

---

## 🔍 根本原因分析

### 问题发现

通过系统性分析，我发现：

**MedicalAiService 已优化**：
- ✅ 已添加 customHeaders 支持
- ✅ 已使用带 customHeaders 的 LLM 客户端
- ✅ `/api/medical-ai/chat` 接口可以正常工作

**TcmService 未优化**：
- ❌ **没有添加 customHeaders 支持**
- ❌ **没有使用带 customHeaders 的 LLM 客户端**
- ❌ **TcmController 没有提取和传递 customHeaders**
- ❌ `/api/tcm/analyze` 接口调用失败

### 技术原因

根据 `coze-coding-dev-sdk` 文档要求：

> **必须在后端 Controller 中提取并转发请求头**，这对于 API 调用的身份验证和上下文传播是必需的。

**LLM API 调用失败流程**：

```
用户点击"生成健康方案"
  ↓
前端调用 /api/tcm/analyze
  ↓
TcmController 接收请求（❌ 没有提取 customHeaders）
  ↓
TcmService.analyzeSymptoms() 被调用
  ↓
创建 LLM 客户端（❌ 没有传递 customHeaders）
  ↓
调用 LLM API（❌ 缺少必要的请求头）
  ↓
API 返回错误码 190000007 (no permission)
  ↓
捕获异常，返回"获取健康方案失败"
```

**错误码说明**：
- **错误码 190000007**：`no permission`
- **原因**：API 无法验证请求身份，缺少必要的请求头
- **影响**：所有依赖 LLM 的功能都会失败

#### 1.2 添加 customHeaders 属性

```typescript
@Injectable()
export class TcmService {
  private llmClient: LLMClient;
  private searchClient: SearchClient;
  private supabase = getSupabaseClient();
  private customHeaders: Record<string, string> = {}; // 新增

  constructor(private abuseDetectionService: AbuseDetectionService) {
    console.log('=== TcmService 初始化 ===');

    // 从环境变量获取配置
    const apiKey = process.env.COZE_WORKLOAD_IDENTITY_API_KEY;
    const baseUrl = process.env.COZE_INTEGRATION_BASE_URL;
    const modelBaseUrl = process.env.COZE_INTEGRATION_MODEL_BASE_URL;

    console.log('API Key:', apiKey ? `${apiKey.substring(0, 20)}...` : '未配置');
    console.log('Base URL:', baseUrl);
    console.log('Model Base URL:', modelBaseUrl);

    // 创建配置并手动设置参数
    const config = new Config();
    if (baseUrl) {
      (config as any).baseUrl = baseUrl;
    }
    if (modelBaseUrl) {
      (config as any).modelBaseUrl = modelBaseUrl;
    }

    try {
      this.llmClient = new LLMClient(config);
      this.searchClient = new SearchClient(config);
      console.log('TcmService LLM 初始化成功');
    } catch (error) {
      console.error('TcmService LLM 初始化失败:', error);
      throw error;
    }
  }

  /**
   * 设置自定义请求头（从 Controller 调用）
   */
  setCustomHeaders(headers: Record<string, string>) {
    this.customHeaders = headers;
    console.log('TcmService CustomHeaders 已设置:', Object.keys(headers).join(', '));
  }

  /**
   * 创建带 customHeaders 的 LLM 客户端
   */
  private createLLMClient(): LLMClient {
    const config = new Config();
    const baseUrl = process.env.COZE_INTEGRATION_BASE_URL;
    const modelBaseUrl = process.env.COZE_INTEGRATION_MODEL_BASE_URL;

    if (baseUrl) {
      (config as any).baseUrl = baseUrl;
    }
    if (modelBaseUrl) {
      (config as any).modelBaseUrl = modelBaseUrl;
    }

    return new LLMClient(config, this.customHeaders);
  }
```

## 🎯 关键技术点

### 1. HeaderUtils 的使用

```typescript
import { HeaderUtils } from 'coze-coding-dev-sdk';

// 在 Controller 中提取请求头
const customHeaders = HeaderUtils.extractForwardHeaders(req.headers);

// 传递给 Service
this.tcmService.setCustomHeaders(customHeaders);
```

### 2. 创建带 customHeaders 的 LLM 客户端

```typescript
private createLLMClient(): LLMClient {
  const config = new Config();
  // 设置环境变量
  if (baseUrl) {
    (config as any).baseUrl = baseUrl;
  }
  if (modelBaseUrl) {
    (config as any).modelBaseUrl = modelBaseUrl;
  }

  // 传递 customHeaders
  return new LLMClient(config, this.customHeaders);
}
```

### 3. 每次调用都创建新的 LLM 客户端

**原因**：
- customHeaders 可能在每次请求时不同
- 需要确保每次调用都使用最新的请求头

**最佳实践**：
```typescript
// ✅ 正确：每次调用都创建新的客户端
const llmClient = this.createLLMClient();
const response = await llmClient.invoke(messages, options);

// ❌ 错误：使用同一个客户端
const response = await this.llmClient.invoke(messages, options);
```
