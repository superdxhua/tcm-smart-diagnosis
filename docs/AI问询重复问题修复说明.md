# AI 问询重复问题修复说明

## 问题描述

**用户反馈**：
- AI 问询阶段重复问同样的问题
- 即使已经回答过的问题，AI 还会再次询问
- 问询无法自动结束，用户一直被问询

---

## 问题分析

### 根本原因

1. **前端没有检测结束条件**
   - 前端在收到 AI 的回复后，没有检测是否包含"信息已收集完毕"
   - 即便 AI 说了"信息已收集完毕，可以进入下一步"，用户仍然可以继续回答
   - AI 没有记忆之前的结束宣告，会继续问询

2. **Follow-up 消息干扰**
   - 每次用户回答后，前端都会添加一个 follow-up 消息："你已经问了 X 个问题，请根据用户的回答决定下一步..."
   - 这些 follow-up 消息累积起来，可能导致 AI 混淆

3. **对话历史过长**
   - 每一轮对话都会添加 2 条消息（用户回答 + follow-up）
   - 对话历史越来越长，可能超出模型的上下文限制

---

## 解决方案

### 修改 1：添加结束条件检测

**文件**：`src/pages/index/index.tsx`

**修改内容**：
在 `handleSendInquiryAnswer` 函数中，添加对 AI 回复的结束条件检测。

**修改前**：
```typescript
if (res.statusCode === 200 && res.data.data) {
  const aiResponse = res.data.data.content || res.data.data
  // 更新对话历史（添加 AI 的回应）
  setAiInquiryMessages([
    ...messagesWithFollowUp,
    { role: 'assistant', content: aiResponse }
  ])
}
```

**修改后**：
```typescript
if (res.statusCode === 200 && res.data.data) {
  const aiResponse = res.data.data.content || res.data.data

  // 🚨 CRITICAL: 检测 AI 是否说了"信息已收集完毕"
  const isInquiryEnded = aiResponse.includes('信息已收集完毕') || aiResponse.includes('可以进入下一步')

  if (isInquiryEnded) {
    // 更新对话历史（包含结束宣告）
    setAiInquiryMessages([
      ...messagesWithFollowUp,
      { role: 'assistant', content: aiResponse }
    ])

    // 提示用户问询已结束，并自动进入下一步
    Taro.showModal({
      title: '问询完成',
      content: 'AI 智能问询已完成，信息已收集完毕。是否继续生成健康方案？',
      confirmText: '继续',
      cancelText: '查看问询记录',
      success: (modalRes) => {
        if (modalRes.confirm) {
          // 进入第五步：获取健康方案
          setCurrentStep(5)
          // 自动生成健康方案
          setTimeout(() => {
            handleGenerateTreatmentPlan()
          }, 500)
        }
      }
    })
  } else {
    // 更新对话历史（继续问询）
    setAiInquiryMessages([
      ...messagesWithFollowUp,
      { role: 'assistant', content: aiResponse }
    ])
  }
}
```

**效果**：
- ✅ AI 说"信息已收集完毕"时，立即提示用户
- ✅ 自动进入下一步，避免用户继续回答导致重复问询
- ✅ 用户可以选择"查看问询记录"或"继续生成健康方案"

### 修改 2：优化 System Prompt

**文件**：`src/pages/index/index.tsx`

**修改内容**：
在 system prompt 中，添加更明确的"防止重复问询"规则。

**修改前**：
```markdown
【问询规则】：
1. **逐个问询**：每次只提出一个问题，等待用户回答
2. **避免重复**：记住已经问过的问题，不要重复询问相同或相似的问题
3. **根据回答调整**：根据用户的回答，决定下一个问什么问题，不要按固定顺序
4. **问询上限**：最多问 10 个问题，不要无限制问询
5. **及时结束**：当收集到足够的信息能够辨证时，立即结束问询
```

**修改后**：
```markdown
【问询规则】（必须严格遵守）：
1. **逐个问询**：每次只提出一个问题，等待用户回答
2. **🚨 禁止重复**：记住已经问过的问题，严格禁止重复询问相同或相似的问题
3. **根据回答调整**：根据用户的回答，决定下一个问什么问题，不要按固定顺序
4. **问询上限**：最多问 10 个问题，不要无限制问询
5. **及时结束**：当收集到足够的信息能够辨证时，立即结束问询

【🚨 防止重复问询的关键策略】：
- 在提问前，先回顾之前的对话历史，确认是否已经问过类似问题
- 如果之前已经询问过"疼痛部位"，不要再问"哪里不舒服"
- 如果之前已经询问过"诱因"，不要再问"什么原因引起的"
- 每次提问前，先思考："这个问题我之前问过吗？"
```

**效果**：
- ✅ 更强调"禁止重复"的重要性
- ✅ 提供具体的示例，帮助 AI 理解什么是"相似问题"
- ✅ 强制 AI 在每次提问前先回顾对话历史

### 修改 3：优化 Follow-up 消息

**文件**：`src/pages/index/index.tsx`

**修改内容**：
优化 follow-up 消息，让 AI 更清楚地理解当前状态和防止重复问询的规则。

**修改前**：
```markdown
你已经问了 ${questionCount} 个问题，请根据用户的回答决定下一步：

1. 如果已经收集到足够的信息（至少 3 个问题，且收集了症状特点、诱因、伴随症状中的至少两类信息），请明确说明"信息已收集完毕，可以进入下一步"
2. 如果需要更多信息，请提出下一个问题（不要重复问询相同的问题）
3. 如果已问了 10 个问题，必须结束问询

请继续：
```

**修改后**：
```markdown
【问询状态提醒】
- 你已经问了 ${questionCount} 个问题
- 用户刚刚回答了：${userAnswer}

【下一步决策】（必须选择其一）：
1. ✅ 如果已经收集到足够的信息（至少 3 个问题，且收集了症状特点、诱因、伴随症状中的至少两类信息），请明确说明："信息已收集完毕，可以进入下一步"
2. ❓ 如果需要更多信息，请提出下一个问题（🚨 严格禁止重复问询相同或相似的问题）
3. ⏹️ 如果已问了 10 个问题，必须结束问询

【🚨 防止重复问询】：
- 回顾之前的对话，确认是否已问过类似问题
- 不要问用户已经明确回答过的内容
- 每次提问前先思考："这个问题我之前问过吗？"

请继续：
```

**效果**：
- ✅ 更清晰地展示当前问询状态
- ✅ 强调"必须选择其一"，避免 AI 模糊决策
- ✅ 使用符号（✅❓⏹️）和表情（🚨）增强视觉效果
- ✅ 明确显示用户的最新回答，帮助 AI 记忆

## 测试方法

### 测试场景 1：正常问询流程

1. 用户填写基本信息（姓名、性别、年龄、主诉等）
2. 点击"开始 AI 智能问询"
3. AI 提出第一个问题
4. 用户回答
5. AI 提出第二个问题（不重复第一个问题）
6. 用户回答
7. AI 提出第三个问题（不重复前两个问题）
8. 用户回答
9. AI 检测到信息已收集完毕，说"信息已收集完毕，可以进入下一步"
10. ✅ 弹出提示框："AI 智能问询已完成，信息已收集完毕。是否继续生成健康方案？"
11. ✅ 用户点击"继续"，自动进入第五步并生成健康方案

**预期结果**：
- ✅ AI 不会重复问同样的问题
- ✅ AI 在收集到足够信息后自动结束问询
- ✅ 弹出提示框，用户可以选择继续或查看记录

---

### 测试场景 2：重复问询测试

1. 用户填写基本信息（姓名、性别、年龄、主诉：头痛）
2. 点击"开始 AI 智能问询"
3. AI 问："请问您的头痛是胀痛、刺痛还是隐痛？"
4. 用户回答："胀痛"
5. AI 问："请问头痛的诱因是什么？"
6. 用户回答："受凉后加重"
7. AI 问："请问头痛的部位在哪里？"（不重复"头痛性质"的问题）
8. ✅ **不重复问**："请问您的头痛是胀痛、刺痛还是隐痛？"

**预期结果**：
- ✅ AI 不会重复问已经回答过的问题
- ✅ AI 会根据用户回答提出新的问题

---

### 测试场景 3：提前结束问询

1. 用户填写基本信息（姓名、性别、年龄、主诉：头痛，现病史：已详细描述症状、诱因、伴随症状）
2. 点击"开始 AI 智能问询"
3. AI 可能只问 1-2 个问题
4. ✅ AI 提前结束："信息已收集完毕，可以进入下一步"（因为用户已经提供了足够信息）

**预期结果**：
- ✅ AI 不会机械地问满 3 个问题
- ✅ AI 根据用户提供的详细信息提前结束问询

## 总结

### 修改效果

| 问题 | 修改前 | 修改后 |
|------|--------|--------|
| AI 重复问同样的问题 | ❌ 经常重复 | ✅ 严格禁止 |
| 问询无法自动结束 | ❌ 一直问询 | ✅ 自动检测结束条件 |
| 用户无法感知问询完成 | ❌ 没有提示 | ✅ 弹出提示框 |
| AI 没有记忆之前的回答 | ❌ 容易遗忘 | ✅ 强制回顾对话历史 |

---

### 技术要点

1. **结束条件检测**
   - 使用 `includes()` 检测 AI 回复中的关键词
   - 关键词："信息已收集完毕"、"可以进入下一步"

2. **System Prompt 优化**
   - 使用表情符号（🚨）强调重要规则
   - 提供具体示例，帮助 AI 理解"相似问题"

3. **Follow-up 消息优化**
   - 使用符号（✅❓⏹️）增强视觉效果
   - 明确显示用户的最新回答
   - 强制 AI 在提问前回顾对话历史

---

### 后续优化建议

1. **对话历史管理**
   - 考虑压缩对话历史（如只保留最近 N 轮对话）
   - 避免对话历史过长超出模型的上下文限制

2. **问询进度可视化**
   - 显示"已问 X 个问题"的进度条
   - 让用户直观了解问询进度

3. **用户主动结束**
   - 添加"我已回答完毕"按钮
   - 用户可以主动结束问询，不依赖 AI 判断

4. **问询质量评分**
   - 收集用户对 AI 问询质量的反馈
   - 不断优化问询策略和提示词
