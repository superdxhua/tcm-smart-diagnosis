# Qwen-Med-Jingfang 微调模型架构设计

## 核心原则
Qwen 是"经方思维的放大器"，而非"通用聊天机器人"

必须构建 "经方专用微调层 + 安全护栏 + 结构化输出管道"

---

## 一、微调模型架构

### 1.1 基础模型选择
- **Qwen-7B-Chat**: 适合轻量化部署，响应速度快
- **Qwen-14B-Chat**: 平衡性能与资源消耗
- **Qwen-Max**: 性能最强，适合云端部署

### 1.2 微调技术路径
- **技术**: LoRA (Low-Rank Adaptation)
- **优势**: 保留通用能力，注入经方专识，参数效率高
- **训练框架**: PEFT + Transformers + PyTorch

### 1.4 微调目标

#### 目标 1: 经方术语体系掌握
- ✅ 拒绝使用西医术语（如不说"免疫力低"，而说"卫阳不足"）
- ✅ 使用六经辨证术语（太阳、阳明、少阳、太阴、少阴、厥阴）
- ✅ 使用八纲辨证术语（表里、寒热、虚实、阴阳）
- ✅ 使用经方方剂名称（桂枝汤、麻黄汤、小柴胡汤等）

#### 目标 2: 六经传变逻辑掌握
- ✅ 掌握太阳 → 少阳 → 阳明传变路径
- ✅ 掌握太阳 → 太阴 → 少阴传变路径
- ✅ 掌握误治变证（误汗、误下、误吐）
- ✅ 掌握合病、并病、坏病辨证

#### 目标 3: 拒绝超纲处方
- ✅ 仅推荐经典经方（桂枝汤、麻黄汤、小柴胡汤等）
- ✅ 仅使用经方药物（麻黄、桂枝、附子等）
- ✅ 拒绝自行组合非经方药物
- ✅ 拒绝推荐非药典药物

#### 目标 4: 结构化输出能力
- ✅ 输出 JSON 格式（诊断、方剂、调护）
- ✅ 输出自然语言（患者可理解）
- ✅ 双通道输出（患者版 + 系统版）

## 四、部署方案

### 4.1 本地部署（适合小规模）
- **模型**: Qwen-7B-Chat + LoRA
- **硬件**: 16GB GPU
- **框架**: vLLM（推理加速）
- **响应时间**: ~3秒

### 4.2 云端部署（适合大规模）
- **模型**: Qwen-Max（阿里云）
- **API**: 通义千问 API
- **成本**: 按调用量计费
- **响应时间**: ~2秒

### 4.3 混合部署（推荐）
- **高并发**: Qwen-Max（云端）
- **低并发**: Qwen-7B-Chat + LoRA（本地）
- **成本优化**: 动态路由

## 五、持续学习机制

### 5.1 专家反馈收集
- 收集专家对诊断结果的评分（1-5分）
- 收集专家的修正建议
- 收集真实世界病例的疗效反馈

### 5.2 模型权重更新
- 定期（每月）使用新数据微调模型
- 使用专家反馈调整模型权重
- 使用真实世界病例优化辨证逻辑

### 5.3 版本管理
- 保留历史版本（支持回滚）
- A/B 测试新版本
- 灰度发布

## 六、伦理与合规

### 6.1 免责声明
- "本建议由AI辅助生成，仅供参考，不能替代执业中医师面诊。"

### 6.2 不开放自主开方权
- AI 可推荐"经典经方加减"，但不可组合新方
- AI 不可使用非药典药物

### 6.3 医师审核接口
- 输出结果可一键发送至合作中医师复核
- 形成"AI初筛 + 人终审"闭环
